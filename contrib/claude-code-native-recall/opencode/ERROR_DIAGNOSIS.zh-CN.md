已知10400 tokens与两个未知预留69632全部保留在同一个阶段预算中；恢复不清零、不重放两次不明请求。最初100k是保守试验目标，父任务后续明确授权本阶段仍最多20请求、已知+未知保守预留最多200k，决策及原计数均有日志。

修复措施：

1. 原生测试工具只接受短参数`{"fixture":"native-long-v1"}`，在本地生成确定性长原文与隐藏proof。长I段是工具内部输出数据，绝不称作模型长参数；成功工具真实参数28字符。原有2010字符失败参数的完整归档单独验证。
2. 工具输出使用官方允许的纯字符串`output`及同一`content`，避免JSON对象的转义表示导致全文检查假失败。
3. HTTP守卫区分provider error envelope、JSON/SSE语法错误、流/计量失败；未来错误只记录有界脱敏的error字段，过滤凭据、Bearer、长标识，完全不记录请求认证头。新增无网络检查验证string/object错误包与脱敏行为。此前丢失的错误信息不能补造。
4. 未知请求仍保留原34816/次预留。任何新错误仍锁停，不自动循环重试。修正后的新显式合成会话不是重放旧请求。

修正后一次真实cycle连续6个HTTP请求均成功：原生本地工具、SEEDED回复、真正manual compaction摘要模型、search、get和最终回答。真实compaction.ended、活动context切换、完整原文和答案联合检查PASS。这支持修复后的可运行性，但不能反推前两次未知流错误的具体服务端原因，也不等于账单核验。
