持久化分三类：`events.jsonl` 是事实来源；`index.sqlite3` 是可重建的插件本地索引和游标；`turns.jsonl` 是派生阅读视图。SQLite 不保存唯一原文，也不引用 bili 的状态。摘要、规则和待办沿用原机制，没有扩展为新的记忆系统。

### 数据保留与身份

完整保存宿主 JSON 对象的所有字段及内容类型；它是语义结构保留，不保证源 JSON 的空白、字段排列或字节编码形式不变。工具输入不再截断到 2000 字符。工具输出、中文、未知非文本块、嵌入附件内容均保留。附件同时记录 `embedded_in_record`、`reference_only_not_fetched`、`content_unavailable`，不会把路径或 URL 冒充永久备份。

事件带宿主、来源项目目录、会话、分支、事件 id、来源路径、代次、字节位置和行号。已有宿主 UUID 用于跨轮换重叠去重，UUID 相同但内容变化保留两个版本。无 UUID 时按来源版本与位置保存，不按文本内容全局合并；同文件不同位置的相同事件分别保留，新 inode 的同内容事件也分别可读。

主会话视图保持原轮次接口，事件版本可在同一逻辑轮中展示；用户事件的原文修订不会静默覆盖旧版本。无 UUID 且同 inode 重写时，相同行号、相同内容的视图会合并，事实档案仍保留各代记录。在宿主没有稳定标识时无法证明它是重发还是新事件，不能承诺全部歧义都可消除。子链单独保存分支状态，其原始事件可读 `events.jsonl`；本阶段 MCP 仍检索主会话，不新增分支选择接口。

### 增量和故障恢复

同步先校验已消费来源前缀。来源截短、重写或 inode 轮换时重新读取并记录新代；旧原文不被删除。没有末尾换行的行、跨写入的 UTF-8 字符和损坏来源行都停在原位置，下次重试；损坏行后面的数据暂不归档，可从返回的 `deferred` 位置诊断。

同一会话的同步与档案读写采用文件锁。原始记录先 flush/fsync，再提交 SQLite 游标；进程在两者之间失败时，从已写原文恢复索引后继续，避免重复追加。索引可损坏隔离后重建；损坏/半行的原始尾部先备份到 `events.corrupt.*.bin` 再截除损坏后缀，之后可从尚存来源重新同步。完整档案删除后不能凭索引恢复原文。

当前只主动校验已提交档案末尾 4 KiB 及新追加部分，不能自动修复任意位置的磁盘损坏；更早位置的坏字节可能令读取明确报错。未来格式版本会拒绝读取而保留文件，不做破坏式降级。相同会话 id 不允许绑定另一来源项目；路径校验拒绝穿越、符号链接和非规则 transcript。直接 hook/core 调用接受宿主提供的绝对普通 `.jsonl` 路径，这是受信宿主接口；MCP 不接受任意 transcript 路径参数，只在当前项目目录寻找来源。

## 迁移、兼容和回滚

1. 首次同步旧会话时，将原 `turns.jsonl` 原字节备份为 `turns.legacy-v0.jsonl`，把可解析旧轮次作为 legacy 事件追加，标明可能截断/缺少非文本内容。无法解析的旧行仍留在备份，不能声称可检索。
2. 旧轮次放在新原文之前，旧数据不靠推测与新原文去重，因此可能重复；备份不因迁移中断而被重写，恢复后补齐尚未迁移的行。
3. `recall_get/search/status/rule/compact_ready` 的名称与参数保持兼容。默认选择收紧：当前项目多会话时必须显式传 `session_id`；未提供项目环境且只有一个存档时保留兼容选择。显式历史存档读取仍可跨会话；`scope=all` 是明确授权的全会话搜索。
4. 重建：停止相关 hook/MCP 进程，保留 `events.jsonl` 与 legacy 备份，删除该会话的 `index.sqlite3` 及其 sidecar、`turns.jsonl`；重启后 `recall_get/search` 会从事实档案重建内存视图，下一次同步重新生成磁盘视图。不能删除事实档案当作“清理索引”。
5. 回滚代码：停止进程，先备份整个 recall 会话目录，再切回基线代码。需要迁移前旧视图时，将 `turns.legacy-v0.jsonl` 的副本恢复为 `turns.jsonl`；保留新 `events.jsonl` 以便未来重新升级。旧代码不理解新原始档案，不要让它继续重建覆盖后再声称新历史仍可由旧工具检索。
6. 本地开发未修改插件版本号或执行 marketplace 更新。可在隔离客户端从本 checkout 加载；正式安装/发布留待单独授权。

## 性能样本

一次 Linux 云端、2400 个合成事件、来源 5,009,160 字节的样本：

| 操作 | 耗时 | 原文档案新增字节 | 原文档案行为 |
| --- | --- | --- | --- |
| 首次同步 | 0.125941 秒 | 7,685,447 | 追加 2400 条 |
| 增加一个用户事件 | 0.004911 秒 | 1,203 | 同 inode，只追加一条 |
| 再次同步，无变化 | 0.004498 秒 | 0 | 大小和 mtime 不变 |
| 内存重建 1201 轮视图 | 0.097859 秒 | 不适用 | 读取完整事实档案 |

增量同步仍读取约 5 MB 来源前缀用于一致性校验。派生视图会在同步入口按需重写，读 MCP 时从事实档案重建；大历史的读取与视图处理仍是 O(n)。以上是单次样本，不是通用延迟保证。

## 免费模型验证和下一阶段

独立代理从官方 npm 包安装了隔离的 OpenCode V2.2.5，匿名模型目录列出了免费选项。实际请求 `models.opencode.ai` 与 `opencode.ai` 时，云端出口代理对 CONNECT 返回 HTTP 403。操作状态为 **denied**；已停止该路线，没有绕过限制，没有账号注册、密钥读取、付费调用或用户历史上传。模型 smoke 没有得到文本响应，不能声称免费模型或 OpenCode harness 验证通过。本地 JSONRPC 成功仅证明本插件协议与合成档案连接，不证明 CC 或 OC 原生压缩生命周期。

下一阶段仍是 ready 原子提交与成功校验、过期检测、有限暂缓和降级、压缩完成确认、恢复幂等及统一恢复预算。本次没有抢做这些机制，也没有接入 OC/DSH 原生适配、向量库、云同步或主动替换历史。
