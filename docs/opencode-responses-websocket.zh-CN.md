# OpenCode V2 Responses WebSocket 接入（#1844）

## 已批准范围

用户于 2026-10-01 授权实现双端 WebSocket ACP 接入：OpenCode V2 到 bili、
bili 到 OpenAI Responses 上游均使用 WebSocket，包括 ChatGPT OAuth/Codex
端点。不实现 Realtime、通用透明帧转发，也不修改用户现用 OpenCode 配置。

## 关键设计

- V2 握手钩子通过已有显式协议隧道路由连接，并附带原生插件身份与模型信息。
  其它协议、退出插件的情形及旧宿主保留原行为。
- 首版只接受本机、原生 OpenCode Responses 连接，复用既有隧道目的地安全
  检查。未接管升级仍立即返回 426，与 #1472 的透明转发方案相互独立。
- Responses 帧经进程内 HTTP 形状适配进入既有 ACP 请求流程，不产生网络
  HTTP 中间跳。异步作用域中的传输适配器把模型请求、预检和重试发送至上游
  WebSocket；既有 ACP 策略、工具执行、统计和正文过滤仍是唯一权威。
  工具参数字符串不经过清理。
- 客户端与上游分别保存连接级检查点。客户端增量先还原为完整历史；上游只有
  在处理后输入确实延续其检查点时才发送增量。压缩或其它历史编辑后发送完整
  处理后输入，不继续旧 previous_response_id，无需因此重开连接。
- 引用标签也可能改变上一轮助手消息，因此复用连接不保证每轮都只发送增量。
- 标记 `view=ws-expanded` 的请求大小日志描述还原后的处理视图，不代表增量
  WebSocket 实际传输字节数。
- 只有成功完成的响应建立检查点。断线、取消、失败、未完成响应或未知响应 ID
  不伪造成功历史；检查点和缓冲均有大小限制。
- 两侧检查点按输出索引累计 `response.output_item.done`，结束事件的
  `response.output` 为空、缺省或不完整时仍保留已完成工具调用，避免下轮增量的
  工具结果失去对应调用。结束事件按 item ID 合并，流式帧保持原样。
  调试日志仅记录检查点补齐的项目数量，不记录内容。
- WS 诊断标明本地连接与会话、失败阶段（握手、等待首事件、流中或分派）、数值
  关闭码、全量/增量请求模式，以及检查点重置和恢复原因。不记录认证头、URL、
  关闭原因原文、请求内容或上游错误正文。正常生命周期与恢复使用 debug，失败
  使用 warn。
- 不增加或改变运行时配置字段、环境变量、包版本、持久化格式或 acp-kernel
  版本。ws 是构建时内联依赖，不增加外置运行时依赖。

## 验证

使用随机回环端口与假 Responses WebSocket 上游，不使用真实凭据或模型额度。
证明双端 WebSocket、增量续接、实际 ACP 折叠后重建响应链、工具参数保真、
用量统计以及未接管升级保留 426；覆盖代理出口、TLS、错误、取消、重连、
检查点丢失与会话隔离。
同时验证结束事件输出不完整时，压缩后的连续工具调用及结果仍能进入后续历史。

真实 OpenCode V2 二进制使用隔离配置，假上游必须成功建立 WebSocket，不能
把连接失败后回退 HTTP 当作证据。交付运行类型检查、完整单测、构建及客户端
端到端测试，并提交人工审查 PR；若真实 Responses 上游不可达，明确记录该
验收缺口，不声称完成线上 OpenAI/ChatGPT 验证。

异常组合覆盖：工具参数交付后断线、失败/未完成终态、取消后立即以轮换的模拟
凭据新建连接、重叠请求、续接/连接寿命错误连续发生时的重试上限，以及握手被拒
后恢复。稀疏终态的真实压缩测试还连续注入检查点丢失、空闲断线和连接轮换，
确认摘要保留且每对已完成调用/结果在上游历史中仅出现一次。
这些验证的是传输和历史，不代表任意宿主工具副作用的严格仅执行一次保证，也
不代替真实 OAuth 刷新生命周期验证。
