Follow-ups: incremental-lane stamping, fork `cloneRows` number-preserving copy, and the one-time legacy re-mint window handling — tracked in #4316.

### Storage — 行身份与史官化(#4390,storage review 四个 p2 + 三个顺路 p3)

- **行身份去污染(D4-1)**:统一存储 messages 行新增 `identity` 列——跨保存 JOIN 键改为**位置无关**序列化(剥离 `id`/`wireIndex` 后哈希)。此前身份掺入 wire 位置元数据,客户端头部截断一条消息就会让后续全部行换血(旧行被清扫、seq 重铸、#4335 的区间账记随之抖动)。`content_hash` 保持字节忠实 CAS 键不变。存量库 v8 迁移:回填 identity 并合并 wireIndex 分裂世代(保最低 seq,重复行退还 CAS 引用)。MySQL 同款(information_schema 探测幂等 ALTER + 回填)。
- **权威集清扫改墓碑(D4-2)**:proxy 会话每轮全量保存不再物理 DELETE 缺席行,改为 `retired_at` 墓碑——rewind/undo 的历史在统一存储里**耐久保留**;同一身份回来时原地复活(保原 seq,含 completeLog-less 保存路径 remap 复活)。读面(getMessages/统一重放/视图)默认过滤 retired;CAS 引用不释放。deleteSession/archive/GC 继续拥有物理生命周期。
- **渲染接缝图片真指纹(D4-3)**:snapshot-render 的 identitySig 图片段从 `长度` 改为 `sha256(base64) 前 24 hex`——同尺寸截图不再可能连击假接缝造成静默截断。
- **fork 谱系入正史(D3-2)**:sessions 行的 `parent_session_id` 现在从信封 `metadata.derivedFromSessionId` 落库(此前恒 null,谱系只活在信封里,信封丢失=家族失忆)。
- **顺路**:gc full vacuum 走 `vacuum('full')`(带 TRUNCATE checkpoint,文件真正缩小,D5-1);loadLegacyView 尾指针缺行从静默缩水改为计数 + 三处加载路径 warn(D4-5);fold-reconcile 的 Pass 0 位置副本失步(存储 ids 与顺序骨架不再 1:1)从静默降级改为响亮 warn(此前无任何日志痕迹)。
- **审查修复(review)**:identity JOIN 迁移后,全量 ingest 对「identity 相同、字节不同」的行原本靠 INSERT OR IGNORE 静默保留旧世代——头部截断后存储世代带着旧 wireIndex 与活视图永久失配(采样校验漂移→水位反复清零→#4323 信封冻结的数据丢失向量),外部 CAS 损坏也永远无法自愈。现在全量路径在**同一 seq** 上采纳更新的字节(seq 稳定性不变,delta 追加路径仍只增不改);`tailGaps` 诊断键从 parity 摘要面剔除(存在性差异不再误报漂移)。
- 测试:`tests/storage-review-p2s.test.ts` 7 桩(截断保号/墓碑+复活/接缝指纹/谱系/迁移去重/gc checkpoint/缺行响亮);storage 全家族 + golden/snapshot/fold-reconcile/incremental/web 回归绿。

### Changes

- **kernel: aged compress receipts fold (#4348).** `compress` exchanges previously enjoyed a hard-coded, age-independent folding exemption (`ALWAYS_PROTECTED_TOOLS`), so every successful compression receipt stayed on the wire forever — a long session accumulated hundreds of `[Compressed mX-mY ...]` stubs (measured: 148 receipts / ~170K chars riding every request) that no range could reclaim, and ranges over them died with "Range would split N turn(s)" once the receipts interleaved with re-anchored coverage. Now only the newest `COMPRESS_EXCHANGE_KEEP_RECENT = 3` compress exchanges keep the exemption (working memory: the model can still see what it just folded); older exchanges fold like ordinary tool messages, with call+receipt+reasoning kept whole by the existing turn-integrity gate. The summaries the model wrote live on verbatim in the rendered block anchors, so decompress/search lose nothing. Host `protectedTools`/`isToolProtected` patterns still win for non-compress tools; for compress-dialect exchanges the kernel aging policy outranks host pinning (same doctrine as #4289 — without it, MCP-lane forms pinned via the host `isToolProtected` hook could never age out). `acp_rule` keeps its blanket exemption.

### Changed (storage correctness wave 3, #4242)

- **State hydration can no longer drift from `mergeState`** (#4192): `COMPRESSION_STATE_FIELDS` in the new `src/state-hydration.ts` is derived mechanically from `Object.keys(mergeState(createInitialState()))` — the ingest/restore field list is generated from the same source as hydration, so a future field can never be restored-but-never-ingested (the `sweptOrphanCallIds`/`pendingOrphanSweepMinRef` loss class). Pinned by a parity test that fails the moment `createInitialState()` grows a key the list does not know.
- **CAS orphans are deleted the moment their refcount hits zero** (#3987): `releaseContent` now deletes the row on the same statement (`UPDATE … RETURNING` + delete on 0) on both the sqlite and mysql backends. Follows the FK discipline strictly — referencing rows are now always deleted *before* their content is released (five call sites reordered), so a zero-ref row can never be dropped while a surviving row still points at it.
- **Reap-shape sessions keep advancing instead of freezing** (#4216): blockContents that outlive their blocks (the #2695 reap shape) now ride the ingest plan as `sessions.orphans_json` — merged (`∪`, because LazyBlockContents may trim entries from memory) in the same transaction as everything else. The mirror skip, the async-twin skip, the importRecord skip and the #3818 writerOff JSON safety valve are all gone: the shape is representable, so `writerOff`'s "the index can represent everything I write" contract holds without an escape hatch. Cold loads after a reap now serve fresh state (the freeze-at-`requests=390` repro is pinned).
- **Raw wire sidecars join the media CAS** (#4069): `splitMediaContent` now also swaps every `data:<mime>;base64,<payload>` occurrence ≥2 KiB inside `rawOpenaiContent` / `rawOpenaiContentParts` / `rawResponsesItem` / `rawGoogleParts` for `{$media:<hash>}` markers; hydration restores the bytes byte-identically on both backends. A picture used to be stored twice (top-level `imageBase64` + the raw sidecar data URL), capping dedup at ~1.89× — the raw sidecar now references the same CAS row (33.8× on the issue's corpus shape). Pinned: no payload bytes in the stored JSON, byte-identical round-trip, shared-row refcount=2.
- **Full-mode authority over a tampered envelope is now pinned** (#4004): the four legacy-envelope integrity tests (`proxy-persist` ×3, `issue2129` ×1) pin `storage.unified=legacy` — they assert the envelope guard layer, which full mode legitimately supersedes; a new test pins the decided semantics instead (index serves while it holds the record; only when both carriers are gone/tampered does the load reject). These were flaky-by-construction under the #3818 full default.
- test: storage-render goldens regenerated once — the drift is inherited from master (#4198 headroom revert changed the stats/metadata shape inside fold-turn bodies), not from this PR; full==legacy==goldens still holds on every wire.

### 压缩

- **过小的陈旧 usage 样本不再冻结计量(#4383)**:同一会话 id 下的小而真实的 usage-grade 样本(标题生成/探测等侧车请求)被 settleUsageReport 无条件写进 lastUsageGradeTokens,所有输入基线读者(statusInputBaseline / effectiveTokenCount)原样信任——kernel 的 growth reference 是低水位标记(#1595)会跟到该值,growth ≡0、压力带失效,自动折叠整段停摆(复现:一次 4733-token 样本把 303k 上下文冻在 usage=1% 达 4h07m,154 次 nudge 全部 idle、零折叠;换模型前重启也不愈合)。现在两个共享读者都走同一个 stale-small 守卫:锚点低于当前出站 billing-caliber 本地估算(contextEstimateTokens)的 25%、且已被其后的一次主发送超越(contextTokensSource="estimate"——主发送逐次盖章、settle 翻回 "usage")时,降级为该估算值——即 #1595 书面承诺的"改用本地估算"兜底。新鲜度闸门区分"陈旧侧车样本"与"新鲜小样本"(后者保持权威,#1820 B 不变量有测试钉死);高于估算的锚点保持 #1839 优先(单向);无估算/无新鲜度戳的旧会话行为逐字节不变。preflight 本就自校正(max(baselineFloor, calibratedPayload)),不受影响;kernel 未动,无新增配置。
- **压缩区间跨越受保护消息时在边界截断,不再挖洞(#3953)**:此前模型选的区间如果中途扫过受保护消息(最近 N 条/最近一条用户消息),受保护消息会被从覆盖名单里挖掉、两侧照折——其回复(在受保护提问之后的消息)被摘要盖住,而摘要锚点落在提问之前,模型看到"答案摘要排在自己的问题上方"。现在区间在首个受保护消息处截断:从该位置起(受保护消息与其后的回复)全部保持可见,因果序不再被打穿。受保护消息恰在区间尾部的常规擦边(咨询式保护区原本设计的形状)行为逐字节不变;截断会清空区间或会劈开工具调用/结果对的形状退回原挖洞语义(吸收保护的吸收对不受影响)。
- **compress-from-store：被逐出的会话对着统一存储的原始视图折叠，不再永久拒收（#3982，根治 #3918 Phase 4）**：超过常驻池预算（默认 512 MiB）的大会话每次模型请求后都被逐出，活内存视图永不存活，`compress` 工具因此永久 REFUSED——而统一存储（#3911）本就每次保存把完整原始客户端视图镜像进 messages 表。现在 applyRanges 与外部摘要链在"有效视图为空"时先从统一正史恢复视图（只读、只窥探——绝不隐式建库；任一行不可解析维持诚实拒收），折叠落在持久化 state 上，与"下一轮模型请求后重试"路径完全同构。活视图在场时存储从不被咨询（零行为变化）；无存储/legacy 模式拒收回执逐字节不变。

### Changes

- **bili-authored dsh client compaction: the #1729 guard can now ANSWER instead of refuse (#3733, fixes #3723's growth loop).** dsh's own compaction was refused locally since #1729 because a landed dsh checkpoint durably shadows the raw history; post-#3644 that substrate concern is gone (the server snapshot is the base), but a native checkpoint is still a foreign summary and — worse — with the refusal standing, dsh's context gauge only grows while its session file balloons unboundedly (#3723: a 39.7 MB / 9001-message file choked the desktop UI). With `BILI_DSH_AUTHORED_COMPACTION=1` (env-only rollout window, read per-request), when the guard fires AND the session holds an active fold block, bili answers the compaction summarize call LOCALLY — zero egress, the autoModeForge discipline — with OUR folded snapshot as the payload: one identity header line `<bili-snapshot v1 conv="…" seq="…" blocks="…" />` plus every active block's summary in the kernel render format. dsh records that as its checkpoint, so the client file shrinks while the recorded content is byte-identical to what the upstream already reads — client display, model context and server state finally agree. The identity tag rides in the message text, so replay recognition is declarative (`carriesBiliSnapshotCheckpoint`, the #2621 carrier+novelty discipline): the #2432 rebase handles the landing exactly like a foreign checkpoint but records `dshAuthoredCheckpointLanded` and logs info instead of warn. Precedence: an explicit `allowDshCompaction` (forward natively) still wins; no active blocks → falls through to the same 422; the passthrough-lane guard (no session) is untouched. Originals stay recoverable via CCR/export/fork; `dshCompactionRefusedBytes` keeps recording the raw-ledger high-water on authored answers too, so the #2490 output-clamp regimes keep planning against the raw scale.
- **存储收尾六修+缺省模式翻 full（#3818，修复 #3135）**：`storage.unified` 缺省从 shadow 翻为 full——shadow 干跑自 #2815 起对账干净，索引成为默认加载路径；JSON 信封照写，legacy 仍是一行逃生口。同车修六项：①writerOff 存档在边车 3-strike 自禁用的当拍立即补写 JSON 信封（消除「两边都没有」窗口）；②BILI_PERSIST=0/持久化关闭视为有意退出（banner 不再假报降级）；③存档印章改为实例真实印章（边车开不了/自禁用→盖 legacy，不再把请求模式盖到只存在 JSON 上的记录上）；④verifyDrift 计数上 /__bili/status wire，漂移会话回退信封供数直到下次采样干净；⑤自举缓存损坏（Node 大版本升级等）从「警告并永不再试」改为删缓存重下一次钉死下载（sha512 保证重试安全）；⑥有界 boot 并入纯索引会话（jsonWriter=off 用户的会话重启后可枚举；并入仍受 maxSessions+解码字节双预算约束，预算口径=序列化记录字节，与文件路径 #2803 同律）。加保：索引无法忠实表达的记录（blockContents 带孤儿 id、state.blocks 无对应块——手搓档案/web seeds 形状）跳过镜像与 viewFor 重建，永远从 JSON 信封供数（orphanSkips 计数可见）——修掉该形状首载后 contents 静默丢失。真实 #2695 收割形状（块从 state.blocks 移除、原文保留给 decompress 兜底）同样命中该守卫并被钉为『永不入索引』语义；writerOff 下该形状触发安全阀强制落一份 JSON 信封（索引跳过+无文件=零副本死亡的窗口不存在）。
- **`bili claude` stops leaking a proxy and a CA into the child it spawns.** The claude lane routes over a plain http loopback URL (`ANTHROPIC_BASE_URL` → `/bili/…`), so there is no TLS hop for a proxy to tunnel and no certificate for `NODE_EXTRA_CA_CERTS` to vouch for. What the bili-owned `HTTPS_PROXY` did there depended on the client build — older ones ignored it, Claude Code ≥ 2.1.301 honours it and the `/bili/` leg self-tunnelled (#3446) — and in every case the variable was inherited by each process the child spawned, so in-session `curl`/`git`/`npm` issued CONNECT through bili's MITM, logging CONNECT destinations the compression pipeline never sees. Both are gone from the claude env; a user's own proxy variables now ride through untouched, and a child that has none of its own is handed the proxy THIS instance resolves for auxiliary egress (file-config `upstreamProxy`, or the shell proxy the launcher forwards as `BILI_INHERITED_*`) via a new `auxProxy` field on `/__bili/health` — so egress survives without bili sitting in the child's path. Keeping the `/bili/` leg direct when the child DOES carry a proxy is the `NO_PROXY` loopback merge in `buildClientEnv` (#3446), which holds whatever proxy the child brings. **Attaching to a proxy instance started by an older build** reports no `auxProxy`, and then nothing is handed over rather than guessing — restart the proxy on this build if your only proxy comes from the config file.

- **Failed-compress receipts now name the live compressible span (#1026, slimmed port of PR #1008 by asuan-dev)**: a model whose compress call fails kept anchoring on refs an earlier fold already consumed — it re-issued the same dead range, burned retries, and eventually gave up and let the nudge re-fire every turn (observed live 2026-09-18: three consecutive failed compresses, two full T1 checkpoints wasted). Skipped entirely under a `bili` launch (`BILLION_CONTEXT_PROXY`/`BILI_PROVIDER_REWRITES` set) — `bili pi` keeps injecting `dist/agent/pi.js` as before. `ensureProxyRunning` gained `deps.scriptPath` (inside pi, `process.argv[1]` is pi's own script, not the package bin). Coexistence: the legacy `billion-context-pi` adapter detects the proxy via a `/bili/` baseUrl prefix or `BILLION_CONTEXT_PROXY`, both invisible under native mode (fetch-layer rewrite; env written asynchronously) — so BOTH installed used to mean double compression. `bili plugin install pi` removes the legacy entry, and the synchronous `BILLION_CONTEXT_NATIVE=pi` marker (see above) lets the standalone extension stand down at action time once it adopts the check.
### Fixes

- **pi native mode: a failed mid-session respawn degrades to direct sends instead of rethrowing the proxy's network error (#513 audit)**: when the spawned proxy died and the one-shot respawn also failed, the interceptor logged an `onDispatch(url, "direct")` but then re-threw the original `TypeError` — the model call died instead of degrading, and `BILLION_CONTEXT_PROXY` stayed set, so the event-time `session_before_compact` cancel kept cancelling native compaction while all traffic went direct (context grows uncompressed, forever). The give-up path now sends the request direct (same contract as bootstrap failure, one-time warning) and fires a new `onGiveUp` hook; pi-native uses it to clear the env so event-time ownership checks disarm together with the traffic. Also: rebuilding a Request-object input against the rewritten target no longer routes caller-side defects (already-consumed or locked body) into the proxy-death branch — they surface as-is instead of respawning an orphaned proxy.
- **Proactive nudge fires on upstreams that NEVER report usage — no more unbounded climb to the hard limit (#728)**: ChatGPT-login-style backends omit `usage.input_tokens` entirely (`response.completed` carries none), so `lastInputTokens` stayed 0 for the whole session — and the kernel's `decideNudge` is structurally unfireable at tokenCount == 0 (growth reference falls back to tokenCount itself → growth ≡ 0; mass-ready and all pressure bands require usage ≥ their pct lines). Proactive compression therefore never fired and contexts climbed unbounded until preflight's hard-limit emergency path took over (#726 reached ~1.32M tokens against a 1.05M window before the ~630K-token emergency summarization — which then 502-looped). `effectiveTokenCount` fed 0 for explicit-identity zero-baseline sessions on the "self-heals via the next measured usage report" assumption, which breaks for never-reporting upstreams. The fix mirrors how OpenAI handles exactly this in codex itself (server-observed usage first-class, local estimator fallback underneath — verified against `openai/codex` sources during triage): each `prepare*` now records the char-count upper bound of THAT turn's outbound payload (post-fold processed messages + system/tools overhead + image tokens) into `session.stats.localInputEstimate`, and `effectiveTokenCount` feeds it ONLY while `lastInputTokens == 0`, capped by the current request's inbound upper bound so a stale-high reading can't outlive a client-side shrink. Real usage always takes precedence the moment any report lands (same invariant as #604's `armFailureShrink` exception — the upper-bound estimator only errs early, compresses earlier, never later); turn 1 of a fresh explicit session is byte-identical to before (nothing measured yet → still 0); anonymous-prefix-affinity forks keep their raw-inbound-bound regime untouched; the estimate self-corrects after every fold (post-fold outbound payload shrinks → next reading drops, no inflation even though proxy clients re-send full raw history every turn); it is cleared on the native-compaction-boundary reset. Net effect: silent-backend sessions get incremental compression from the moment the local estimate crosses the nudge thresholds instead of one giant emergency fold at the wall. Rebase onto current master exposed an interaction with #817's per-body preflight dead-end cooldown key: the nudge text injected into the system prompt changes every turn, so keying the cooldown on the sha256 of the proxy-REBUILT wire body misses on identical client retries once the fallback arms the nudge — every retry re-burned the doomed summarization walk, defeating #726's quota protection on exactly the silent backends this fix targets. The cooldown identity now hashes the client's raw inbound request body instead, so proxy-side injections (nudge/system/tools/tags) can no longer defeat it. Tests pin: silent-backend multi-turn (turn 1 idle → turn 2 nudges, preflight silent), real-usage precedence (reported tokens beat a ~90% payload), stale-high cap (shrunk history does not re-trigger).
- **Bump acp-kernel 0.0.74 → 0.0.77; `acp_cache` held off every wire surface until adoption (#800)**: the pin jumps three kernel releases — 0.0.75 (cache-reconciliation core: `acp_cache` tool + `buildCacheReport`; recommend tail-below-gate fix), 0.0.76 (Google/Gemini wire codec; recommend range integrity), 0.0.77 (nudge ranges ordered/merged by position instead of ref number — fixes #887). Kernel ≥0.0.75 ships a fifth proxy tool, `acp_cache`, but this proxy has no execution path for it: an intercepted call fell through `executeProxyTool` into the unknown-tool branch, which reports SUCCESS with `[Unknown proxy tool: acp_cache]` — a model calling it would get a plausible-looking result that did nothing. Until adoption lands (feature #800, owner decision pending), `src/compress-tool.ts` derives `PROXY_TOOL_NAMES` and the four `BILI_ACP_TOOLS_*` arrays from the kernel constants minus `UNADOPTED_KERNEL_TOOLS` (`{acp_cache}`) — the single choke point every serving surface consumes (Responses/OpenAI/Anthropic tool arrays, plugin manifest + allowed list, absorb gate, Responses-adapter classification), so the tool stays off the wire everywhere without touching call sites. `MUTATING_PROXY_TOOLS`/`READONLY_PROXY_TOOLS` stay raw re-exports (classification sets only; `acp_cache` is correctly classified readonly and no serving surface reads them). The #841 parity test (`tests/search-context-cross-session.test.ts`) extends the "no other tool may change" contract against the FILTERED kernel side only, so a future BILI-side leak of an unadopted tool still fails.
- **A render tag wrapped around the model's whole turn no longer reaches the client as orphan markup (PR #872)**: a model imitating the render tag can write its entire turn — tool call included — where the opening's attributes are still open (recorded shape: `<acp tokens="1" text="text` immediately followed by the turn's own markup). The span escapes every tag pattern at once: an attribute class stops at `<`, and the value opened with `"` is never closed, so no close tag is ever written. The filter dropped the opening and released the payload, and the agent received a completed turn of orphan `parameter`/`invoke`/`calls` closers with no tool call in it — it stalled until nudged by hand. The stripper now recognises the wrapped shape by form (the attribute list runs into a `<`, or carries an odd number of quotes) and swallows the span whole, to a loose close tag or to the end of the turn, in `stripAcpTags` and in the streaming filter alike; the turn then reaches the client empty, which the degenerate-turn retry (#870, PR #871) re-asks for. The #644 rule is unchanged: an over-long tail after a *plain* opening is still released as content.

- **Preflight fold budget raised 8 → 16: a payload far over the window can now be brought under it (#868, PR #869)**: one range folds per round and both per-invocation budgets were 8, so the loop gave up before finishing even when every fold succeeded. A live Gemini session (1.39M-token payload against a 1,048,576 window) folded 8 ranges, saved ~329k tokens, landed ~8k short of the window, and then fail-fast 502'd with `the compress budget was exhausted after 8 rounds` — a message that also read misleadingly, because it quoted the ORIGINAL context rather than the folded size. `MAX_PREFLIGHT_ROUNDS` and `MAX_SUMMARY_CALLS_PER_PREFLIGHT` are now 16 (`src/preflight.ts`, both exported so budget tests derive from them); the fail-fast 502 now reports the post-fold size ("~N tokens (down from ~M before preflight)") and the remaining compressible-range count (`result.rangesRemaining`) instead of only the original token count; the fold-depth coverage bound (best case ~9.6x-window overshoot, lower in practice) is documented beside the constants. `tests/preflight-round-budget.test.ts` pins the behaviour on the openai wire: an ~83k-token fixture against a 30k window is refused at 8 rounds and forwarded at 16, using more than 8 summary calls; a second case scales the same history past the 16-round bound and pins the honest 502 (post-fold size, remaining-range count, exactly 16 summary calls); the #574 budget-cap case in `tests/preflight-multi-range.test.ts` no longer re-pins the literal 8.
- **Plugin passthrough re-issues a turn whose only visible output was a stripped tag echo (#870, PR #871)**: the plugin-mode direct pipe strips model-emitted render tags, and when that echo was a turn's ENTIRE visible content the emptied chunk was suppressed, so the host received a turn with no text and no tool call and aborted it. Releasing the echo instead is not an option (the #463 contract keeps a pure-echo turn swallowed, and #674/#673 forbid leaking the echo as content), so the pipe now re-issues: on a clean terminal (`stop` / `end_turn` / `stop_sequence`) with zero visible text, zero tool calls and no error finish reason, `src/plugin.ts` refetches the same request with a continuation nudge (`src/degenerate-retry.ts`: `DEGENERATE_RETRY_NUDGE`, `injectContinuationNudge`, `makeContinuationRefetch`) and relays the retry inside the original framing — Anthropic keeps a single `message_start`/`message_stop` with the retry's block indices offset, and the OpenAI terminal is the `choices[].finish_reason` chunk rather than `[DONE]`, so the first attempt's terminal never reaches the client twice. One retry per turn; if the retry is also empty the original turn passes through with the existing `[degenerate-turn]` warning, and an unissuable retry presents the original terminal with valid JSON. `appendTrailingUserText` moved to `src/wire-body.ts` so the fake-completion hint and the retry share one body builder. Tests: `tests/plugin-empty-turn-retry.test.ts` (8, driving the pipe with a fake response and a fake refetch).
 The same gate now covers the unclosed case: when a render tag is dropped and its interior
  survives as the turn's only visible text, the host receives orphan markup with no tool call and
  stalls, so that interior is counted as markup rather than as visible output and the turn is re-issued. When the retry degenerates too, the client now receives an in-band stream error rather
  than a silent empty turn: an empty turn is indistinguishable from a model that produced nothing,
  and the host reports neither, so the session reads as idle while it is dead.
- **Degenerate-turn auto-retry reachable on OpenAI/Anthropic wires (#821, PR #822)**: the #732 invisible single-retry for a completed turn containing ONLY a thinking block (zero visible text, zero tool calls) was unreachable on the OpenAI/Anthropic wires: its gate required `!forwardedAny`, but on those wires reasoning deltas are forwarded verbatim to the client, so at `done` time both `forwardedAny` and `sawThinking` are true — mutually exclusive for exactly the shape this retry exists for. Only the Responses wire (round>1 framing suppression) could ever fire it. Wild-caught via WorkBuddy + deepseek-v4.1-flash through an OpenAI-chat gateway: two round-1 thinking-only turns (~6–8 min of thinking, zero visible output) logged the #673 `[degenerate-turn]` warning but passed through as empty turns, and the host aborted with an "empty stream" error. The loop now tracks model-VISIBLE output separately (`forwardedVisible`, set only on text forwards; reasoning/meta keep setting `forwardedAny`), and the retry gate uses it — a forwarded thinking prefix is invisible to host turn semantics and its chunks carry no `finish_reason` (adapters strip it), so appending the retry's content to the same stream is safe. Unchanged: one-shot bound, mandatory `sawThinking` (a genuinely empty no-reasoning turn still passes through untouched), and the #413 truncation retry's strict `!forwardedAny`. Regression tests pin the openai-wire round-1 shape (retry fires, nudge present, thinking prefix precedes retried content in the same stream) and the no-reasoning control (no retry).
- **Cross-process startup-window race: concurrent launches no longer double-spawn proxies (#707)**: `ensureProxyRunning` only attached when it found a *healthy* instance at probe time — between the launcher's spawn and the child's first successful listen there was zero on-disk evidence that a bring-up was in flight, so two launches inside that window (~1s+) each spawned their own child: two live proxies over one sessions dir (double writers), last-writer-wins instance file, and the extra proxy living until ITS OWN spawner exited. The starter now claims `<state>/proxy-starting` with O_EXCL before spawning (carrying `{token, pid, host, port, startedAt}`); a concurrent caller that sees an active marker (owner pid alive AND younger than SPAWN_WAIT_MS + 30s) waits for the starter's instance with the same probe as attach (pid alive + `/__bili/health` + instanceId match), bounded by SPAWN_WAIT_MS, and attaches on success; marker disappearance (starter gave up / crashed) breaks the wait early so the caller spawns immediately. The starter clears the marker on every terminal path via a token-checked clear; a hard crash leaves a stale marker that the dead-owner/TTL checks render inert. The O_EXCL claim itself is the cross-process arbiter: the pre-spawn read is only a fast path, so a loser of the claim (read→claim race, or a stale/garbage marker file left by a crash mid-write) re-checks and either waits for the live holder or removes-and-reclaims the slot — it never spawns blindly, and an unreadable marker file self-heals on the next launch instead of permanently degrading coordination. A final probe after the wait deadline catches a starter that succeeded in its last moments — its success path clears the marker, which otherwise looks identical to a failure bail. Incompatible-config fall-through is preserved (a waited-for instance that isn't compatible with our launch options still spawns, matching today's incompatible-healthy-instance behavior); explicit `bili start` bypasses the marker entirely (it's a user action, not auto-bootstrap). In-process dedup (`singleFlight`, #706) is untouched — this is the cross-process half.
- **DeepSeek thinking mode 400 fixed: turns are atomic, reasoning-drop self-disables on strict-echo upstreams (#684)**: two paths could ship a rebuilt request whose assistant `tool_calls` turn lost its `reasoning_content` — (1) the proxy's recent-zone carve kept the last tool-call of a multi-call turn visible while its reasoning run folded into the block (kernel boundary logic only pulled the FIRST companion message after reasoning), and (2) #651's reasoning-drop stripped reasoning from a closed compress turn even on upstreams that document thinking-mode `reasoning_content` as mandatory round-trip. DeepSeek rejects both with 400 (`The \`reasoning_content\` in the thinking mode must be passed back to the API`) and the turn dies. Fixes: the kernel now computes atomic turn groups (reasoning run + its full assistant burst + every result paired by `toolCallId` — all fold together or none do; a range that would split a turn is withdrawn with a warning, or rejected with an explanatory error when nothing else remains), the forward boundary pull covers the whole burst, and the reasoning-drop never fires when the session is known strict-echo — statically for `deepseek` upstreams, or learned from the first 400 whose body mentions `reasoning_content` (persisted on the session, self-healing like #552). Three wire-level exit sentinels (`[reasoning-pair-violated]` on chat/completions and Responses, `[thinking-pair-violated]` on Anthropic) log loudly if any future path reintroduces a split turn.
- **Windows: spaced client/extension paths no longer break launched clients or silently drop extensions (#679, PR #682)**: `runClient` spawned clients with `shell: true` and no per-token quoting, so on Windows cmd.exe re-split the joined line at the first space — a client binary under a spaced path (`C:\Users\John Doe\...`) died with `'C:\Users\John' is not recognized`, and a surviving client whose `-e <extension>` path was split launched WITHOUT the bili extension (compression silently never activates). Spawning is now routed by executable class: real `.exe`/node binaries spawn directly (the OS quotes argv, spaces intact), npm `.cmd`/`.bat`/extensionless shims go through an explicit `comspec /d /s /c "…"` line with correct per-token quoting (`windowsVerbatimArguments`); `shell: true` is gone (also silences Node's DEP0190 warning). Known edge: `BILI_CLIENT_BIN` pointing at a `.js` file now fails loudly instead of relying on file association via the old shell path.
- **Windows: codex MCP server delivered via CODEX_HOME overlay, not inline `-c` (#681, PR #683)**: cmd.exe cannot transmit a literal `"` to a child, but every valid TOML string needs one — so the inline `-c mcp_servers.bili.command="C:\\Program Files\\nodejs\\node.exe"` arg arrived at codex as an unquoted, space-split, invalid TOML value for ANY absolute Windows path (spaced stock install just the common case), the bili MCP server never registered, and plugin-mode compression silently never activated. On `win32` the launcher now writes `[mcp_servers.bili]` (command/args/env.BILI_MCP_PROXY/env.BILI_CONVERSATION_ID) into a persistent `<CODEX_HOME>-bili` overlay's merged `config.toml` — sharing every other real-home entry (auth.json, sessions, model settings) — and points the spawned codex at it via `CODEX_HOME`. POSIX keeps the working inline `-c` path byte-identical; if the overlay can't be built the launch degrades to wire mode (server-side compression still active) with a warning. Real-Windows end-to-end verification tracked in #686.
- **`bili plugin install codex` self-heals malformed config blocks instead of short-circuiting (#638, PR #685)**: the "already installed" check compared only the `BILI_MCP_PROXY` line, so a malformed `[mcp_servers.bili]` block (e.g. `args` written as a quoted string — legal TOML, invalid codex schema) survived reinstall untouched and codex kept failing with `expected a sequence`. The whole block is now compared against the canonical `codexBlock()` (trimEnd-normalized): byte-equal → `already installed`; anything else → rewritten in place, with an explicit `(repaired args: was not an array)` hint when args was string-valued.
- **codex reports the folded request's own usage — #408 uncompressed-baseline backfill suppressed for codex (#645, PR #647)**: codex fell through every #408 backfill exemption, so its context meter showed a virtual cumulative baseline the model never receives — drifting turn-to-turn (the meter could DECREASE with no compress), exceeding the window (1315/950k = 138%), and driving nothing (codex auto-compact keys off `total_tokens`, which the backfill never touches). `armHostUsageCredit` now exempts codex clients — detected by UA, the same signal as native-compact interception, because bili-launched codex sessions carry `pluginAgent:"mcp"` shared with claude. `isCodexClient` also gained a lenient fallback (UA containing `codex`, case-sensitive) so new codex client variants (codex_sdk_ts/…) can't silently fall out of detection. Plain proxy clients keep the #408 behavior; `hostUsageCredit:"off"` (#648) still opts out entirely.
- **Upstream fetch no longer follows redirects on the client's behalf (#661, PR #664)**: `fetchWithTimeout` left `redirect` unset, so undici's default `"follow"` kicked in — a 301/302/303 on a POST was downgraded to GET with the body dropped, and the redirect target (a POST-only API behind a CDN/WAF) answered **405**. A forward proxy must hand the 3xx (status + `Location`) back to the client; `redirect:"manual"` now does exactly that.
- **Codex (ChatGPT-login) preflight summaries work end-to-end (#663, PR #665)**: the ChatGPT codex backend rejects the Responses `max_output_tokens` parameter outright (400), killing preflight summaries with a 502 — the proxy now detects that rejection, retries the summary without the optional parameter, and learns it per session+upstream+model (bounded, at most once per capability). The summary call also no longer forwards the Codex-Lite header (`x-openai-internal-codex-responses-lite`) that demands `reasoning.context: all_turns` the summary body doesn't carry — stripped from the independently-built summary call only; the main request keeps it.
- **Tag-echo filter tolerates typo'd tag names; degenerate end_turn turns get a warning (#673, PR #674)**: a model echo with a typo'd tag name (an `acp` permutation plus one stray char — `acpi`/`acip`) bypassed every exact-spelling strip pattern, and the 43-char fragment became the turn's ENTIRE visible text (`stop_reason=end_turn`, zero tool_use, the real plan stranded in thinking) — the agent stalls until nudged. All strip patterns now match a programmatically-built acplike name set (66 members, strict name boundaries so `acpi.h`/`<caption>`/`ACPI_DEVICE` in real text stay untouched), the swallow-scan recognizes loose close variants, and a degenerate-turn detector logs `[degenerate-turn]` when a turn carries echo-only text with no tool calls — the groundwork for auto-retry. Follows #644/#646 (v0.1.97 incident family).

### Features

- **Native Google (Gemini) wire support: `generateContent` / `streamGenerateContent` conversations are tracked, folded and compressed (#866, PR #867)**: bili terminated TLS for `generativelanguage.googleapis.com` and forwarded POSTs verbatim, because protocol detection matched only `/chat/completions`, `/v1/messages` and `/responses` — Gemini's `/v1beta/models/<model>:streamGenerateContent` matched nothing, so `protocol` stayed `null`, the kernel path was skipped, the request logged as `[unknown] forward POST →`, and no conversation identity was minted: ACP compression never fired while the plugin cancels the client's own compaction, and a live omp session reached 339k tokens. The kernel now carries a full Gemini codec (`src/wire/google.ts`: `googleToCore` / `coreToGoogle` / `googleSystemText` / `conversationSignalGoogle`, flat `{name,description,parameters}` function declarations, `thoughtSignature` and `thought` sidecars, and same-side run merging because Gemini rejects non-alternating roles); the proxy detects the wire from the URL (`googlePathKind`, `googleModelFromPath`), hoists system text out of the fold space into `systemInstruction`, resolves identity by prefix affinity over `contents` (Gemini clients send no session header, so the header chain cannot apply), maps usage as input = `promptTokenCount` − `cachedContentTokenCount` and output = `candidatesTokenCount` + `thoughtsTokenCount`, treats `generationConfig.maxOutputTokens` as the output budget, replays thinking signatures on re-issued reasoning, and rejects the OpenAI-compatibility shim on purpose: it drops `thoughtSignature` / `extra_content`, which Gemini 3 function calling requires. Two defects that only a live wire exposed were fixed on the same branch: preflight summaries posted to the client's own SSE endpoint (`:streamGenerateContent` answers SSE whatever the request says) were parsed only when `preflightStreamSummary` was set, so every summary read as empty (`carried N SSE event(s) but no summary text`, 8 attempts, then a 502 and a 300s dead-end cooldown) — the response shape now decides the parser (`SSE_DATA_LINE_RE`, `extractSummaryFromSse` vs `extractSummaryText`); and the proxy's synthesized tool result carried only `toolCallId`, so the wire emitted `functionResponse{name:"unknown"}` answering `functionCall{name:"compress"}` and Google rejected the whole request with 400 `INVALID_ARGUMENT` (Gemini pairs calls by name, OpenAI/Anthropic by id). Covered by `tests/wire-google.test.ts`, `tests/adapter-google.test.ts`, `tests/preflight-google-summary.test.ts` and google cases in `tests/preflight-sse-extraction.test.ts`, with `tests/e2e-google-compress.test.ts` carrying a strict Gemini shape validator (alternating roles, one payload per part, signatures only on model parts, `functionResponse` named AND answering a call seen earlier) that reports nine `functionResponse name=unknown answers no call` violations when the name fix is reverted; verified live against `gemini-3.8-flash`, where a proxy-owned `compress` call executed, folded ~97k tokens and was accepted.
- **Image billing modes (`imageBilling` / `BILI_IMAGE_BILLING`): pixel-tile upstreams no longer get permanently 502'd by byte-based image estimates (#767)**: follow-up to #496/#500 — on official Codex/OpenAI/Anthropic upstreams (pixel-tile billing), once a session's historical `lastInputTokens` baseline sits above the window, the default `base64 length / 4` image cost closes BOTH safe-forward paths at once (#496 forward-once requires a sub-window baseline; #300 stale-baseline fit requires `payloadEstimate < limit`), so preflight fails 502 `preflight_compress_failed` ("Images alone account for ~N tokens") forever even though the images bill only a few thousand tokens upstream (repro: two screenshots, byte estimate ~300K vs real billing ~4.4K). New global + per-provider `imageBilling` (`"auto" | "pixels" | "bytes"`; env `BILI_IMAGE_BILLING` overrides both, live-read per request): `pixels` parses the image header (PNG/JPEG/WebP/GIF/BMP, bounded decode — never the full body) and charges first-party high-detail tile billing (512px tiles, short side scaled up to 768px, long side capped at 2048px → 765–2805 tokens per image; unparsable formats fall back to a flat 16384); `bytes` keeps the conservative default so byte-counting relays retain their #488/#496 protection unchanged. `auto` classifies by upstream host (`openai.com` / `openai.azure.com` / `chatgpt.com` / `api.anthropic.com` suffixes → pixels; everything else → bytes). Remote URLs stay flat 4096 in both modes; `BILI_IMAGE_TOKEN_CAP` still clamps on top of both. A stale baseline now self-heals within one turn of pixel-billed traffic (usage reports replace the baseline absolutely), while #496's one-rejection-then-block guarantee for genuine byte-relay overflow is preserved — pinned by regression tests: recovery e2e (stale 696789 baseline + two large screenshots forwards and recovers under `pixels`), bytes-mode control (same payload still fails fast with zero images forwarded), learned-limit-only variant, and env-precedence check.
- **Session-file encryption at rest behind `BILI_ENCRYPTION_KEY` (#708, PR #711)**: for deployments on untrusted nodes, persisted session files (block summaries plus up to ~16k tokens of folded conversation per session — effectively full conversation content) can now be stored as `BILIENC1` AES-256-GCM over zstd-compressed JSON (zstd via built-in node:zlib on Node ≥ 22.15, raw mode byte on older runtimes; compression also shrinks files ~5–10×). The key is env-only — deliberately NO key-file support, since a key file would sit on the same untrusted filesystem as the data — exactly 32 bytes hex or base64, never written to disk or logs; an invalid value aborts startup (fail fast instead of silently running unencrypted). When enabled, boot takes over legacy plaintext files once: each is re-encoded and atomically replaced in place (the rename IS the old-file deletion; a crash mid-migration self-heals on the next boot), covering `.fb.json` spill files too; unreadable files are left in place with a warning. Wrong key at boot → GCM auth failure → affected sessions skip as corrupt (logged, no crash). Mechanism is the kernel's optional `StateStore` codec hook (acp-kernel#249 → 0.0.64); unset key = zero behavior change.
- **Per-route `passthrough` option for providers (#661, PR #662)**: `"providers": { "mitm://zcode.z.ai": { "passthrough": true } }` forwards matching requests byte-for-byte — no kernel round-trip, no render tags, no `prompt_cache_key` removal, response piped verbatim, no session state — the scoped sibling of the global `passthrough` switch. `mitm://` keys target only MITM (login-client) traffic; plain `https://` host keys cover both MITM and `/bili/` traffic.

- **Round-evidence closure for compress-reasoning drop (#651, #348 twin)**: the closure gate shipped with the reasoning drop — "compress call followed by a genuine user message" — is unreachable in long agentic sessions (no user messages after the opening prompt, observed: 0 drops while 30 compress rounds retained 20.6K/8.4K/10.6K-char thinking floors). A round now closes on tool-result evidence: the compress call's `tool-result` (matching `toolCallId`) exists at a later index and at least one message follows it. In-flight rounds (result missing or still the last message) stay untouched; per-provider `compress.providers.<name>.reasoning.drop=false` escape hatch preserved for reasoning-replay models (GLM). Mirrors billion-context-pi #348 (PR #349).
- **`hostUsageCredit` config switch: opt plain proxy clients out of the #408 uncompressed-baseline usage backfill (#648)**: plain anthropic proxy clients (ZCode — base-url → proxy, no `x-bili-plugin` header, no special UA) fell through every #408 backfill exemption (pi/omp by `pluginAgent`, codex by UA in #647) and got the full uncompressed-baseline backfill armed, so their UI showed a cumulative, drifting baseline (real folded value + per-compression backfill) instead of the actually-forwarded context — overstating real pressure and going non-monotonic on pure-append turns (est drift). New `hostUsageCredit` option (`"auto" | "off"`, default `auto` = current behavior; `BILI_HOST_USAGE_CREDIT` env / `hostUsageCredit` file key). `off` disables the #408 backfill entirely so the usage reported to the host is the actually-forwarded (folded) request, matching `[acp-usage] input=`. `auto` keeps today's behavior for everyone; ZCode users set `off` to get the actually-forwarded value.

- **Lenient compress-arg parsing: salvage single-quoted JSON before hard rejection (#603)**: weak local models (reported via omp#121) emit `compress` args with single quotes (`{'content':[{'startId':...}]}`) — a malformation class the kernel's salvage ladder (fences, trailing commas, raw newlines, double-stringification, truncated/prose-wrapped arrays) does not cover, so the whole call was rejected `kind=malformed-json`, the round was wasted, and the model saw a FAILED result that can trigger tag-echoing. `parseCompressInput` now retries once through a quote-normalization pass when the kernel recovers zero ranges or reports invalid items: a state machine converts single-quoted strings to double-quoted ones (apostrophes inside double-quoted values are data and are copied verbatim; control characters inside single-quoted regions become JSON escapes), applied to raw-string args and to object inputs whose `content` value is a stringified array. The retry wins only when it recovers strictly more ranges — valid input is never rewritten — and salvaged ranges pass the same ref-validation gate as any other range, so the worst case is a wasted round, never a wrong compression. A `[acp-compress-input] quote-salvage: recovered N range(s)` warn logs each recovery for attribution.
- **Forward-once-then-learn for image-dominated payloads — no false 502 on pixel-tile upstreams (#496)**: the default per-image estimate (`base64 length / 4`, uncapped) matches byte-billing relays but overestimates pixel-tile upstreams (official Anthropic/OpenAI) by up to ~200×, so a session whose *estimated* image floor alone exceeded the window was hard-failed with a 502 `preflight_compress_failed` ("Images alone account for ~N tokens") even though the real cost was a few K tokens — a regression vs master for official-API multimodal users (e.g. `bili claude` pasting screenshots). The fit gate now forwards ONCE instead of hard-failing when the over-window is attributable solely to the image estimate (`textEstimate < limit`), there is no upstream evidence of overflow yet (`lastInputTokens < limit` and no learned limit for the model), and images are present. The upstream then arbitrates billing: a pixel-tile upstream accepts (usage reports small → zero behavior change); a byte-billing relay rejects once, the existing self-heal learns the true window, and every subsequent request fails fast with an accurate message — exactly one rejected forward, strictly better than master's infinite 400 loop, no new knob. Also documents `BILI_IMAGE_TOKEN_CAP` (per-image estimate cap) in CONFIGURATION.

- **Multimodal sessions: count image bytes in the preflight size gate + stop growing summaries on the Responses wire (#488)**: the preflight fit gate counted only text tokens (`estimateCoreMessages`) while the wire carried base64 images, so a session whose images alone exceeded the window was never caught by the gate, forwarded raw, rejected with `context_window_exceeded`, and self-healed into a learned window smaller than the images' cost — then every later request failed preflight fast and could never forward again (the #488 "infinite 400 loop"). New `src/image-tokens.ts` estimates per-request image tokens (inline `data:` = `base64 length / 4`; remote URLs = flat 4096) across all three wires (Responses `input_image`, OpenAI `image_url`, Anthropic `image`) and feeds them into the fit gate as `imageFloor` and into the output clamp as `imageTokens`; the overflow self-heal now folds the rejected request's image cost into the learned window so a byte-billing relay converges in one rejection instead of looping. The Responses summary payload also gained `store:false` so the proxy's ephemeral compress calls are not persisted upstream.

- **Plugin-mode passthrough strips render-tag echoes on the OpenAI chat-completions and Anthropic wires (issue #14)**: the #206/#295 tag-echo protection only ran on the Responses wire (`pipePluginResponsesWithStrip`) — plugin-mode sessions on `/v1/chat/completions` (pi, omp chat models, dsh) or `/v1/messages` (claude-code via MCP register) received the upstream stream verbatim, so a model that imitates the `<acp …>` render tags in its prose had those echoes land in the agent's replayed history, where they were re-sent to the model, re-imitated, and amplified — observed as the "bili 总是循环 / endless blank output" loop with pi + qwen3.8 (one stored assistant message carried 77 echoed tags + ~3,300 blank lines; the tags render invisibly in the pi UI, so the screen just scrolls blank). Plugin passthrough now routes chat/anthropic streams through `pipePluginChatWithStrip`: events stay byte-identical (the agent's native tool loop still sees tool calls untouched) except `choices[].delta.{content,reasoning_content,reasoning}` / `content_block_delta` `text_delta`/`thinking_delta` text, which streams through the same tag-echo state machine (one filter per field×choice/block index; held tails flush before [DONE]/message_delta/finish as synthetic deltas; echo-only chunks are dropped instead of forwarding empty deltas), and non-streaming JSON bodies strip `choices[].message.*` / `content[].{text,thinking}` the same way `pipePluginJson` already did for Responses. A `[tag-echo]` warn is logged per stripped stream for attribution.

- **Upstream proxy: unset mode now means "direct", not env auto-detect (#346)**: the web UI advertises 直连（默认） for an unset `upstreamProxyMode` (the radio defaults to `direct`) and ZCode's own default is `mode:"direct"`, but the code parsed an unset mode as "no preference" and fell through to env/system proxy auto-detection (`HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`, then the Windows system proxy). A user who never configured a proxy could therefore silently have bili route the upstream through whatever proxy was in the environment (e.g. Clash), changing the egress IP — which breaks IP-bound OAuth on domestic endpoints (the #346 ZCode 401/slow symptom) and contradicts the UI. Unset mode now resolves to `direct` (an empty global proxy short-circuits to direct instead of env discovery). To follow the system/env proxy, set mode `auto` explicitly (web UI 自动（跟随系统） or `BILI_UPSTREAM_PROXY_MODE=auto`); an explicit proxy (`-F` / `BILI_UPSTREAM_PROXY`) still wins regardless of mode. (A top-level `proxy` config still requires mode `auto`/`manual` to take effect — pre-existing, unchanged.) A deduped `[upstream-proxy] <host> via <proxy> (source=<source>)` log line (non-public hosts masked per #255) now makes the resolved proxy visible instead of silent.

- **Logger: rotated log file orphan inode — writes silently drift to `.old` (#210)**: the logger holds a single `WriteStream` (`flags: "a"`) for the life of the process, so once `bili.log` is renamed to `bili.log.old` (internal 10MB rotation, logrotate, a manual rename) the fd points at the renamed inode and every subsequent line lands in `.old` while the fresh `bili.log` sits at 0 bytes until restart — and no `error` event ever fires, because the orphaned fd is still valid, so the old error/writable-based recovery never triggered. The logger now compares the fd's inode (`fstat`) with the current path's inode (`stat`) on every write and, on divergence, explicitly closes the old stream (`end()` first so buffered lines drain into the rotated file) and reopens against the current path. When a (re)open fails (disk full, perms, path clobbered), logging degrades to stderr-only with a single `[warn]` instead of crashing the proxy — both for runtime reopens and the startup `configureLogger` open. Tests: external-rename simulation (new file receives subsequent lines, `.old` frozen), reopen-failure degradation (exactly one warn, no crash), and the internal 10MB rotation regression.
- **Tag-echo filter strips truncated tag fragments (#294)**: the streaming tag-echo filter only stripped complete render tags, so a model echo cut off mid-stream (tag split across SSE chunks) left junk fragments in the output — and the unbounded lone-opening match could swallow an entire message that merely started tag-like, stripping it to empty. Now: (1) a definite unterminated opening (tag name + space, no closing `>` yet) is held across chunks up to 4096 chars instead of being passed through once it grew past the old 128-char hold cap, and dropped (with a warn) beyond that; (2) `flush()` at stream end drops arbitrary truncated openings (including an unclosed `tokens=` quote) and drops content swallowed after an unclosed attrs-bearing opening — a dangling ref fragment is tag content, not prose; (3) the lone-opening match is bounded to 256 chars of attrs, so prose that merely starts with a tag-like opening and contains a `>` later is no longer swallowed up to that `>` (the whole-message-stripped-to-empty case). Ambiguous short prefixes (`<`, `<a`, `</ac`, bare tag name without space) keep the small hold cap and are emitted at flush, so real prose is never delayed or lost; non-streaming JSON rewriters get the same fragment handling.
- **Identity plugin binding survives model switches (one conversation, many sessions)**: an identity registration (`POST /__bili/plugin/register` with `identity: true` — the omp/claude-code path) was consumed one-shot: the first request that carried the conversation id ate the registration and bound ITS session into plugin mode. Switching models or upstreams mid-conversation resolves a NEW session (session key = protocol|upstream|apiKey|conversation) — the registration was already gone, so the omp TUI flow "chat model → responses model" silently dropped back to wire injection (native tools gone, model roleplaying `acp_status` output). Identity registrations are now sticky for the conversation: every request carrying the id binds, LRU-refreshed and bounded by the same 64-entry cap. Wild-caught as "原生模式消失了" after a GLM-chat → qwen-responses model switch.
- **Responses: stamp `type:"message"` on type-less input items at ingress.** omp (pi-ai) sends user items without the spec-required `type` field; the kernel wire projection switches on `item.type` and silently dropped them, so user prompts never entered the compression state (no refs, never tagged, never compressible, invisible to nudge/preflight — #247 testing caught this).

- **Wire the kernel absorb API: instant tool-result compression (#605)**: new opt-in `compress.absorb` block (`enabled` / `minToolTokens` / `contextThresholdPct` / `excludeTools` / `toolName`, cascading global→provider→model) wires the acp-kernel absorb feature: when enabled, large tool results get a forced `[ACP absorb]` instruction at result time, the model distills each into a compact summary via the `absorb` tool, and the original tool-call/tool-result pair is hidden from the wire from the next turn on — keeping mid-session pressure lower between fold rounds. Because the kernel's default rules are load-bearing (tuned over months of production use), overrides are **inert until `acknowledgePromptsRisk: true`** is set at the winning level; without it they are ignored and a one-time warning is logged. ### Fixes

- **Strip model-emitted render tags from plugin-mode passthrough responses**: the plugin-mode direct-pipe path replayed the upstream stream verbatim, bypassing the tag-echo stripper that only lives in the compress-loop stream path — an omp native-mode session (PR bringing omp into plugin mode) re-ingested the model's fake `<acp>` tags verbatim, seeded a tag-echo loop in a fresh session, and crowded out real prose. Responses plugin passthrough now runs the same tag-echo filter (delta-level state machine, done-event payloads flushed and stripped); other events stay byte-identical. The non-streaming plugin JSON path strips the same tags for Responses bodies (parity with the compress loop's JSON branch); a held tag-echo tail is flushed as a final delta if the stream is cut without a done-family event, so prose is never silently lost; multi-line `data:` payloads (never emitted by real upstreams) collapse into the single rebuilt line instead of fusing two JSON payloads.
- **Drop whitespace-only Responses message items at ingress (flattened-turn artifact)**: Responses-API clients that flatten a mixed turn (text + tool calls) into separate `input` items — omp does this, one message item per text block — replay the model's pre-tool-call whitespace (`\n\n`) as standalone 1-token messages. bili then stamps each with a 42-char `<acp>` render tag plus a ref id, a 10x payload bloat of pure noise, and the tag makes the empties sticky (they replay as "non-empty" tag+whitespace forever after). The proxy now strips render tags and drops message items whose remaining text is pure whitespace before projection; tagged real content is never touched. Applies to all Responses clients (pi keeps its block-array structure and is unaffected).

- **Double compress per turn (stale post-compress usage, #252)**: the post-compress re-request deliberately re-sends the UNFOLDED history (prefix-cache friendly — 96% cache hits observed), so its upstream usage report still carries the pre-compress size. That report overwrote `lastInputTokens`, and the nudge gate on the client's NEXT request re-evaluated the stale number → injected the compress philosophy again → the model compressed a second, tiny range in the same logical turn. Compress savings are now tracked as a per-turn credit: `applyRanges` nets them out of `lastInputTokens` immediately, every usage recorder (wire loop, plugin passthrough, non-streaming JSON) nets the credit out of raw reports, and the next request's `processTurn` — where the fold actually materializes — clears it. If the context is genuinely still over-limit after a compress, the nudge still fires (that is correct behavior); cumulative `inputTokens` billing stats stay raw.
- **omp/stateless Responses sessions never compress (prompt_cache_key identity)**: clients that replay full history statelessly with no conversation headers (omp without its plugin loaded) fell through the identity chain to a hash of the ENTIRE input array — which changes every turn, so every request minted a brand-new session (`requests: 1` on dozens of 90%+-full session files). The nudge evaluates token counts BEFORE the first forward of a session, so it always saw 0 tokens (`usage=0%, growth 0 < floor`) and never fired: contexts sat at 92% with zero compressions, while the upstream cache affinity also churned every turn. The Responses `prompt_cache_key` (the client's own stable conversation id) now replaces that fingerprint — real headers, body `session_id`, and `previous_response_id` still win; only the per-request fingerprint fallback is upgraded.
- **acp-loop replay auto-retry on upstream risk-control rejections** (#189): after a `compress`, the acp-loop replay request can be rejected by provider risk-control — GLM Coding Plan returns `400 {"code":3007,"msg":"captcha verify failed"}` ~1s after the big context rewrite — and the error was passed straight into the agent session as `[acp-proxy: compress loop upstream error 400: ...]`. The replay request (both the streaming loop and the Responses-API JSON loop) now retries transient upstream failures with exponential backoff: up to 3 attempts total, base delay 1500ms doubling per attempt, overridable via `BILI_REPLAY_RETRY_BASE_MS` (ms; `0` disables the delay). Transient = HTTP 429/5xx, or any other 4xx whose body matches risk-control markers (`captcha`, `verify failed`, `risk control`, `风控`, `rate limit`, `too many requests`, `try again`); plain 4xx (bad model, bad params) still fail fast with no retry. Each retry logs a clear line (`upstream rejected replay (HTTP 400 ...); likely provider risk-control — retrying in 1500ms (attempt 1/3)`), and if all attempts fail the surfaced error now says `after 3 attempt(s)` so users can tell it was retried. Set `BILI_REPLAY_RETRY_MAX=1` to restore the previous fail-fast behavior.
- **Upstream rejection of replayed thinking blocks (#222, issue #221)**: some upstreams (GLM 4.6 thinking) reject the compress-loop re-request when it carries replayed `thinking` blocks with a 400 (`Invalid parameter: thinking_content …`). The compress loop now strips loop-injected thinking and retries the re-request degraded-first: replay with thinking stripped → on failure retry with reasoning dropped entirely → on failure replay raw; each degradation logs a clear line. Only affects the internal re-request — the client stream keeps the original reasoning blocks.
- **OpenAI SSE tool-call name-split regression (#224)**: some OpenAI-compatible upstreams (SGLang) split the streamed `tool_calls.delta.name` across multiple chunks; the per-chunk proxy-vs-real adjudication dropped split names, so the client received an empty tool name and the agent errored with `Unknown tool ''`. Tool calls are now settled once at `finish_reason` from the fully-buffered deltas: pure-proxy rounds re-emit structured events, real rounds replay the raw chunks verbatim (with `suppressCompletion`), mixed rounds strip only the proxy fragments. Buffer-to-finish also fixes chunk-reordering regressions.

- **Windows `bili codex` ENOENT** (#134): npm globals install as `.cmd`/`.bat` shims on Windows, and Node `spawn` can't resolve a bare name to them (CVE-2024-27980). `resolveClientCommand` now resolves the full `.cmd`/`.bat`/`.exe` path via `resolveOnPath` (using `path.delimiter`, was hardcoded `:`) and spawns with `shell:true` on win32. Fixes `spawn codex ENOENT` for all `bili <client>` launchers on Windows.
- **DeepSeek thinking 400 after compression** (#133): the root cause is in acp-kernel — an assistant turn's `reasoning_content` (emitted as a separate `contentType:"reasoning"` message) could be split from its companion text/tool-call by a compress range, leaving an orphaned half that DeepSeek-thinking rejects with HTTP 400 `"reasoning_content in the thinking mode must be passed back to the API."`. Bumps **acp-kernel to 0.0.23**, which mirrors the existing tool-pair mechanism: `adjustBoundariesForReasoningPairs` expands the compress range so the pair always compresses together, `stripOrphanedReasoning` is a rebuild safety net, and `applyPairBoundaryAdjustments` composes both to a fixpoint. The same latent class is fixed on the Anthropic and Responses paths too.
- **textProtocol suppresses only message items, preserves reasoning/image lifecycle** (#94): the text-protocol stream filter was dropping `reasoning` and `image` content along with the message items it meant to suppress, breaking their lifecycle. Now only `message` items are suppressed; reasoning and image blocks pass through unchanged.
