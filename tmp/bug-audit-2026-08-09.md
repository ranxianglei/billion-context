## 🔴 HIGH severity

### Bug 1 — `cacheHitPct` produces `NaN`, breaks `/__bili/stats` JSON

**File:** `src/server.ts:982`

```ts
cacheHitPct: s.stats.cacheSamples > 0 ? Math.round(s.stats.cachedTokens / s.stats.inputTokens * 100) : null,
```

**Problem:** The guard checks `cacheSamples > 0`, but the divisor is `inputTokens`. When a turn has only cache hits (`cache_read_input_tokens > 0`) and `input_tokens === 0`, this computes `cachedTokens / 0 = Infinity`, and `Math.round(Infinity) = NaN`.

**Impact:** The `/__bili/stats` endpoint emits invalid JSON containing `NaN` (not a valid JSON token). Any client doing `JSON.parse` throws. Affects every web-UI / stats consumer whenever a cache-only turn occurred.

**Fix:** Guard on the divisor:
```ts
cacheHitPct: s.stats.cacheSamples > 0 && s.stats.inputTokens > 0
    ? Math.round(s.stats.cachedTokens / s.stats.inputTokens * 100)
    : null,
```

### Bug 2 — Non-streaming branch: `arrayBuffer()` throw leaks fetch timer and skips `markDirty`

**File:** `src/server.ts:882-901`

```ts
} else {
    const buf = await upstream.arrayBuffer();   // ← can throw (abort / connection reset)
    const text = Buffer.from(buf).toString("utf8");
    try {
        const json = JSON.parse(text);
        ...
        res.end(JSON.stringify(json));
    } catch {
        res.end(text);
    }
    clearUpstreamTimer();        // ← only reached on no-throw
}
markDirty(prepared.session);     // ← also skipped on throw
```

**Problem:** If `upstream.arrayBuffer()` rejects (e.g. the 10-min fetch `AbortController` fires, or the connection resets), the rejection propagates out of `forward()` → `handle()` → the outer `createServer` catch (`server.ts:115`). Both `clearUpstreamTimer()` and `markDirty(prepared.session)` are skipped.

**Impact:**
1. The 10-minute fetch timer keeps running (minor leak; it eventually fires a no-op abort on a dead response).
2. **More serious:** state mutations accumulated during the turn (e.g. a `compress` that created a block earlier in `processTurn`) are never persisted — `markDirty` is skipped, so the compression state is lost on next reload.

**Fix:** Wrap the non-streaming branch body in `try/finally`:
```ts
} else {
    try {
        const buf = await upstream.arrayBuffer();
        const text = Buffer.from(buf).toString("utf8");
        try {
            const json = JSON.parse(text);
            if (prepared.protocol === "openai") rewriteOpenaiJsonResponse(json, ctx);
            else if (prepared.protocol === "responses") rewriteResponsesJsonResponse(json, ctx);
            else rewriteJsonResponse(json, ctx);
            res.end(JSON.stringify(json));
        } catch {
            res.end(text);
        }
    } finally {
        clearUpstreamTimer();
    }
}
markDirty(prepared.session);
```
(Move `markDirty` into the `finally` too if state may have mutated before the throw — but at minimum the timer must be cleared.)

### Bug 3 — MITM: unhandled `error` event on `TLSSocket` crashes the process

**File:** `src/mitm.ts:140-162`

```ts
let tlsSocket: tls.TLSSocket;
try {
    tlsSocket = new tls.TLSSocket(clientSocket, {
        isServer: true,
        secureContext: getSecureContext(host),
        ALPNProtocols: ["http/1.1"],
    });
} catch (e) { ... }
...
server.emit("connection", tlsSocket);   // ← no tlsSocket.on("error", ...) attached
```

**Problem:** The `TLSSocket` wrapping `clientSocket` has no `error` listener. If a client aborts the TLS handshake (common — certificate rejection, network drop), Node emits `'error'` on the `TLSSocket`. With no listener, Node's default behaviour is to **throw an uncaught exception, crashing the entire proxy process**.

**Impact:** Any single non-cooperating client (or any client that disconnects mid-handshake) takes down the whole proxy. This is an availability bug.

**Fix:** Attach an error handler before emitting the connection:
```ts
tlsSocket.on("error", (err) => {
    log(`mitm ${host}:${port} TLS error: ${err.message}`);
    clientSocket.destroy();
});
server.emit("connection", tlsSocket);
```

### Bug 4 — Responses API text-protocol path drops the compress result (orphan `output_text.delta` + empty `output`)

**File:** `src/stream-responses.ts:240-265` (text-protocol) and `src/stream-responses.ts:270-293` (non-text-protocol)

Text-protocol tail:
```ts
if (safeText) {
    out += sse("response.output_text.delta", { item_id: "msg_acp", output_index: 0, delta: safeText });
}
for (const payload of state.triggerPayloads) {
    ...
    out += sse("response.output_text.delta", { item_id: "msg_acp_note", output_index: 0, delta: "\n" + note + "\n" });
}
const base = (state.responseObj ?? { id: "resp_acp" }) as Record<string, unknown>;
const respId = typeof base.id === "string" ? base.id : "resp_acp";
out += sse("response.completed", { response: { ...base, id: respId, status: "completed", output: [] } });
```

**Problem:** In the Responses streaming protocol, a `response.output_text.delta` for a given `item_id` **must** be preceded by a `response.output_item.added` event creating that item (`{ type: "message", id, role, status, content: [] }`). Here the deltas reference `item_id: "msg_acp"` / `"msg_acp_note"`, but no `output_item.added` is ever emitted for those ids. Clients (Codex) key the delta stream on the item created by the `.added` event — without it the deltas are orphaned and silently dropped. Additionally the final `response.completed` sets `output: []`, so even clients that tolerate the deltas lose everything in the final response object.

The non-text-protocol path (line 282) has the same problem: it emits `output_text.delta` keyed on the suppressed compress `function_call`'s `itemId`, which was never emitted as `output_item.added`, and also sets `output: []` at line 290.

**Impact:** When Codex in `code_mode` (text-protocol) triggers a compress, **the entire compression result is invisible to the user** — the client drops the orphan deltas and the `completed` envelope is empty. This makes text-protocol compression appear to do nothing.

**Fix:** Before the first delta, emit the item lifecycle:
```ts
const MSG_ITEM = { id: "msg_acp", type: "message", status: "in_progress", role: "assistant", content: [] };
out += sse("response.output_item.added",  { output_index: 0, item: MSG_ITEM });
out += sse("response.content_part.added", { item_id: "msg_acp", output_index: 0, content_index: 0, part: { type: "output_text", text: "" } });
out += sse("response.output_text.added",  { item_id: "msg_acp", output_index: 0, content_index: 0, text: "" });
// ... deltas ...
out += sse("response.output_text.done",   { item_id: "msg_acp", output_index: 0, content_index: 0, text: fullText });
out += sse("response.content_part.done",  { item_id: "msg_acp", output_index: 0, content_index: 0, part: { type: "output_text", text: fullText } });
out += sse("response.output_item.done",   { output_index: 0, item: { ...MSG_ITEM, status: "completed", content: [{ type: "output_text", text: fullText }] } });
```
And in `response.completed`, set `output:` to `[<the message item>]` instead of `[]`. Apply the same fix to the non-text-protocol path (line 270-293), using a fresh message-item id rather than the suppressed function_call id.

### Bug 5 — `initSessions` sorts by `createdAt`, not `savedAt` as documented

**File:** `src/session.ts:100-105` (comment on line 93)

```ts
/** Bulk-load persisted sessions from disk into the in-memory map. ... Caps at
 *  MAX_SESSIONS by savedAt (keeps the most recent) so a huge backlog cannot
 *  OOM on boot. */
export async function initSessions(): Promise<void> {
    ...
    if (loaded.size > MAX_SESSIONS) {
        const entries = [...loaded.entries()].sort((a, b) => (b[1].createdAt ?? 0) - (a[1].createdAt ?? 0));
        ...
    }
```

**Problem:** The docstring says sessions are capped by `savedAt` (keep most-recently-saved), but the code sorts by `createdAt` (keep most-recently-created). Worse, the `Session` type has **no `savedAt` field at all** — only `PersistedSession` does (`persist.ts:54`), and `buildSession` does not restore it. So even fixing the sort key requires adding the field.

**Impact:** On boot with a backlog larger than `MAX_SESSIONS`, sessions are evicted by creation time, not last-saved time. A very old but recently-active session can be evicted while a recently-created-but-stale one is kept.

**Fix:** Add `savedAt: number` to the `Session` type, set it in `markDirty` / `scheduleSave`, restore it in `buildSession` (`persist.ts:393`), and sort boot-load by it. Or update the comment to match current behaviour.

### Bug 6 — `providerFromHost` suffix match is an unbounded substring check

**File:** `src/registry.ts:116-123`

```ts
export function providerFromHost(host: string): string | undefined {
    const lower = host.toLowerCase();
    if (HOST_TO_PROVIDER[lower]) return HOST_TO_PROVIDER[lower];
    for (const [h, p] of Object.entries(HOST_TO_PROVIDER)) {
        if (lower.endsWith(h) || h.endsWith(lower)) return p;
    }
    return undefined;
}
```

**Problem:** `h.endsWith(lower)` is a pure substring check with no domain boundary. Verified by probe:
```
providerFromHost("penai.com")  → "openai"   // "api.openai.com".endsWith("penai.com") === true
providerFromHost("ai.com")     → likely matches several entries
```
Any host whose name shares a trailing substring with a known provider host is misclassified.

**Impact:** An unrelated or attacker-controlled host that shares a suffix is mapped to the wrong provider, causing `contextFromRegistry` to look up the wrong model key → wrong context window → wrong compression timing. Limited blast radius (only affects when-to-compress), but a real correctness bug.

**Fix:** Require a `.` boundary and drop the reverse match:
```ts
for (const [h, p] of Object.entries(HOST_TO_PROVIDER)) {
    if (lower === h || lower.endsWith("." + h)) return p;
}
```

### Bug 7 — OpenAI stream handler reads only `tool_calls[0]`, drops subsequent tool args

**File:** `src/stream-openai.ts:108-129`

```ts
if (delta && Array.isArray(delta.tool_calls) && delta.tool_calls.length > 0) {
    const entry = delta.tool_calls[0] as {       // ← only index 0
        index?: number;
        function?: { name?: string; arguments?: string };
    };
    const tidx = entry.index ?? 0;
    const name = entry.function?.name;
    ...
    if (state.compressIndices.has(tidx)) {
        const frag = entry.function?.arguments;
        if (typeof frag === "string") state.args[tidx] = (state.args[tidx] ?? "") + frag;
        return null;
    }
    return rawEvent + "\n\n";
}
```

**Problem:** OpenAI can deliver deltas for multiple tool indices in a single SSE chunk (e.g. two tool calls starting in the same delta). This code reads only `tool_calls[0]`; arguments for the second+ tool are silently dropped, so `buildOpenaiTail` reconstructs truncated / invalid JSON for those tools. (The Anthropic and Responses paths iterate correctly.)

**Impact:** When two or more `compress` tool calls are emitted in the same chunk, the second+ call's arguments are corrupted → `JSON.parse` fails → empty `{}` → that range is not compressed.

**Fix:** Loop over all entries:
```ts
if (delta && Array.isArray(delta.tool_calls) && delta.tool_calls.length > 0) {
    let passthrough = rawEvent + "\n\n";
    for (const entry of delta.tool_calls as Array<{ index?: number; function?: { name?: string; arguments?: string } }>) {
        const tidx = entry.index ?? 0;
        const name = entry.function?.name;
        if (typeof name === "string") {
            if (name === COMPRESS_TOOL_NAME) { state.compressIndices.add(tidx); state.converted = true; }
            else state.sawReal = true;
        }
        if (state.compressIndices.has(tidx)) {
            const frag = entry.function?.arguments;
            if (typeof frag === "string") state.args[tidx] = (state.args[tidx] ?? "") + frag;
            passthrough = null;   // this tool's delta is suppressed
        }
    }
    return passthrough;
}
```

## ⚪ Reported but rejected (verified not bugs)

To save upstream review time, these were flagged by automated review but do **not** hold up against the actual code:

- **`anthropic.ts` `buildSystem` drops `cache_control` / replaces content with empty text** — unreachable: the caller only invokes `buildSystem` with a non-empty `text`. The empty-`text` branch is defensive dead code.
- **`stream.ts` `partial_json` keyed by `index` reuses stale buffered JSON** — `content_block_stop` calls `blocks.delete(index)` and `content_block_start` resets `json: ""`, so no stale data survives across blocks at the same index.
- **`stream.ts` `message_delta` double-counts `outputTokens`** — only the non-converted path runs `ctx.session.stats.outputTokens += out`, and `message_delta` arrives once per stream; no double counting.
- **`stream-responses.ts` `drainText` produces negative `cut`** — `holdLen = min(ACP_TEXT_OPEN.length - 1, textPending.length)` guarantees `cut = len - holdLen ≥ 0`; mathematically safe.

## Suggested fix order

1. **Bug 3** — process crash; any single client can take down the proxy. Most urgent.
2. **Bug 1** — fires on any cache-only turn; breaks the stats endpoint JSON.
3. **Bug 2** — timer leak + lost compression persistence on non-streaming errors.
4. **Bug 4** — text-protocol compress result silently invisible to Codex.
5. **Bug 7** — multi-tool-call argument corruption (rare but real).
6. **Bug 6** — provider misclassification on suffix-overlapping hosts.
7. **Bug 5** — boot-time LRU eviction order; mostly cosmetic.

Each fix should ship with a regression test (the existing suite is happy-path-only and misses all of the above).
