How it works

Not a bigger window — a better layout. Four mechanisms keep months of work inside an ordinary context limit:

⊟

Folded, not rewritten

When history outgrows its budget, only the newly consumed slice is folded into a compact summary block — once per block, ever. The window oscillates in a bounded band instead of growing without limit; production sessions ran months at ten-thousand-plus calls. Any block decompresses back to full text when you need the detail.

♰

The provider's cache stays warm

A fold deactivates old ranges without touching the front of the conversation, so the prompt-cache prefix survives turn after turn — 94.2% of active input was served from cache in the study. Rewrite-style compaction invalidates the whole prefix and re-bills it. This does not.

◈

The model decides what to forget

A versioned compression doctrine lives in the system prompt; a growth-gated nudge says when folding pays off. The agent judges what the task still needs, may refuse, and compresses between steps — never mid-step.

∑

Every token is accounted

Each request is sampled into a per-session ledger — new content, cache reads, compression repay, TTL expiry — plotted in percentage points on a trajectory chart. Audit real savings with /acp in the terminal or the built-in web UI at /__bili/.

Up and running in under a minute

One npm package, Node 22+. Then pick your connection style:

1

Native plugin — recommended

Installs straight into your client for the deepest integration: bili plugin install pi. Covers pi · omp · claude · codex · opencode · dsh · kimi · hermes · zcode.

2

Launcher — works for any agent

Wraps your client's command and injects bili automatically, zero config edits: bili pi, bili codex, bili claude — about twenty agents.

3

Generic proxy

Any client that accepts a custom endpoint works out of the box: point its base URL at http://localhost:8787/bili/<your upstream>.
